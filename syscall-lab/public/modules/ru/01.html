Системные вызовы в Linux

Что такое системные вызовы?

Системный вызов (system call, syscall) — это механизм, с помощью которого программа обращается к ядру операционной системы для выполнения привилегированных операций.

Когда вашей программе нужно:

  1. открыть файл,
  2. выделить память,
  3. создать процесс,
  4. отправить данные по сети,
  5. прочитать данные с клавиатуры,

она не делает это напрямую (это невозможно в пользовательском режиме), а обращается к ядру через системный вызов.

Простая аналогия: Системный вызов — это как звонок в службу поддержки отеля. Вы не можете сами зайти в подсобку и взять полотенце, но вы звоните на ресепшн, и сотрудник приносит его вам. Ядро — это ресепшн, а системный вызов — номер телефона.

Зачем нужны системные вызовы?

Причина Объяснение
Безопасность Пользовательская программа не может напрямую манипулировать оборудованием или памятью других процессов. Все операции проходят через ядро, которое проверяет права доступа.
Абстракция Программисту не нужно знать, как именно работает жёсткий диск, сетевая карта или видеокарта. Ядро предоставляет единый интерфейс для работы с устройствами.
Контроль ресурсов Ядро может управлять приоритетами процессов, распределять время CPU, следить за использованием памяти и предотвращать перегрузку системы.
Стабильность Ошибочный код в пользовательской программе не может обрушить всю систему — ядро изолирует процессы друг от друга.

Режимы работы процессора

Современные процессоры поддерживают как минимум два режима работы с разными уровнями привилегий:

Режим Название Что разрешено
Ring 3 Пользовательский режим Ограниченные инструкции, доступ только к своей памяти, запрещён прямой доступ к оборудованию.
Ring 0 Ядерный режим Все инструкции, прямой доступ к памяти и устройствам, управление прерываниями.

Переход из пользовательского режима в ядерный называется переключением контекста (context switch). Это дорогостоящая операция, поэтому системные вызовы стараются делать быстрыми.

На современных 64-битных системах Linux системный вызов выполняется с помощью инструкции syscall (на x86-64). На старых 32-битных системах использовалась инструкция int 0x80.

Как происходит системный вызов?

Процесс выполнения системного вызова можно разбить на несколько этапов. На рисунке 1 показан путь системного вызова от пользовательского пространства до выполнения кода в ядре.

Этапы выполнения системного вызова

Шаг 1. Пользователь вводит команду ls в терминале. Программа ls для получения списка файлов в каталоге вызывает функцию getdents() из стандартной библиотеки C (glibc).

Шаг 2. Библиотека glibc подготавливает аргументы (указатель на буфер для записи записей каталога, размер буфера) и помещает номер системного вызова в регистр процессора:

  1. На x86-64 это регистр rax.
  2. Для системного вызова getdents номер — 78 (определён как __NR_getdents в заголовочных файлах ядра). Для getdents64 (современная версия) номер — 217

Шаг 3. Выполняется специальная инструкция процессора, которая переключает процессор в режим ядра:

  1. На x86-64 — syscall.
  2. На x86 (32-бит) — int 0x80.

Шаг 4. Управление передаётся обработчику системных вызовов в ядре (обычно это функция entry_SYSCALL_64 или system_call).

Шаг 5. Обработчик по номеру 78 (или 217 для getdents64) из регистра rax находит нужную функцию в таблице системных вызовов sys_call_table.

Шаг 6. Выполняется соответствующая функция ядра — sys_getdents() (или sys_getdents64). Она читает содержимое каталога из файловой системы и формирует структуры с именами файлов.

Шаг 7. Результат работы (список файлов в каталоге) возвращается обратно программе ls в пользовательском пространстве.

Шаг 8. Процессор переключается обратно в пользовательский режим. Программа ls получает данные и выводит их на экран в виде таблицы.

Ключевой момент: Всё это происходит за микросекунды, и программа даже не замечает переключения контекста!

Таблица системных вызовов (sys_call_table)

Таблица sys_call_table — это массив указателей на функции ядра. Каждый системный вызов имеет свой номер (индекс в таблице). По этому номеру ядро находит адрес функции-обработчика и передаёт ей управление.

Как ядро находит обработчик?

Когда происходит системный вызов:

  1. Ядро берёт номер из регистра rax.
  2. Использует этот номер как индекс в массиве sys_call_table.
  3. Получает адрес функции-обработчика.
  4. Передаёт управление по этому адресу.

Например, когда программа вызывает openat(), в регистр rax помещается число 257. Ядро обращается к ячейке sys_call_table[257], получает адрес функции sys_openat и запускает её.

Как посмотреть таблицу системных вызовов в своей системе

Выше мы рассмотрели таблицу sys_call_table в теории. Но как увидеть её на своей системе?

В Linux есть несколько способов посмотреть, какие системные вызовы доступны и какие у них номера.

Посмотреть номера системных вызовов

Номера системных вызовов для вашей архитектуры определены в заголовочных файлах ядра.

Для 64-битных систем:

cat /usr/include/x86_64-linux-gnu/asm/unistd_64.h

Для 32-битных систем:

cat /usr/include/x86_64-linux-gnu/asm/unistd_32.h

Пример вывода:

#define __NR_read 0
#define __NR_write 1
#define __NR_open 2
#define __NR_close 3

Посмотреть адреса функций в памяти

Файл /boot/System.map-$(uname -r) содержит адреса всех символов ядра, включая sys_call_table.

grep sys_call_table /boot/System.map-$(uname -r)

Пример вывода:

ffffffff81a001c0 R sys_call_table

Или

ffffffff81a001c0 D sys_call_table

  • D(Data) — символ находится в инициализированной секции данных ядра (.data). Эта секция читаемая и записываемая
  • R(Read-only) — символ находится в секции только для чтения (.rodata). Эта секция только читаемая (попытка записи вызовет kernel panic).

Посмотреть таблицу в отладчике

Если у вас установлен отладчик gdb и отладочные символы ядра, можно загрузить ядро в отладчик и посмотреть таблицу:

gdb /usr/lib/debug/boot/vmlinux-$(uname -r)
(gdb) print sys_call_table

Посмотреть через /proc/kallsyms

Если ваше ядро собрано с поддержкой CONFIG_KALLSYMS (обычно включена), можно посмотреть адреса символов:

cat /proc/kallsyms | grep sys_call_table

Пример вывода:

ffffffff81a001c0 R sys_call_table

В этом способе может быть неожиданный вывод: 

0000000000000000 R sys_call_table

Современные ядра Linux используют механизм KASLR (Kernel Address Space Layout Randomization). Чтобы злоумышленникам было сложнее взломать систему, реальные физические адреса функций и переменных ядра скрыты. Чтобы увидеть реальные адреса, нужно выполнить команду с правами суперпользователя:

sudo cat /proc/kallsyms | grep sys_call_table
